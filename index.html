LINE-Based Barbershop Income and Commission Management System
ผู้จัดทำ: นาย สราวุฒิ อุยยาหาญ (รหัสประจำตัว 674230027, หมู่เรียน 67/44)
อาจารย์ที่ปรึกษา: ผศ.ดร. สุพิชฌาย์ จันทร์เรือง
สาขาวิชาเทคโนโลยีสารสนเทศ คณะวิทยาศาสตร์และเทคโนโลยี มหาวิทยาลัยราชภัฏนครปฐม

ข้อจำกัดของระบบงานแบบดั้งเดิมในร้านตัดผม แบ่งเป็น 3 มิติหลักที่ส่งผลต่อประสิทธิภาพทางธุรกิจ

SLIDE 02 / 20
💸 1. ปัญหาด้านรายรับ (เงินเข้า)
  • ตรวจสลิปขณะติดลูกค้า: ช่างกำลังให้บริการลูกค้า จึงไม่สามารถเปิดแอปธนาคารตรวจยอดเงินจริงได้ทันท่วงที
  • ความเสี่ยงสลิปปลอม/วนใช้ซ้ำ: เสี่ยงต่อการถูกฉ้อโกงด้วยภาพสลิปตัดต่อ และการนำสลิปเก่ามาวนใช้ซ้ำ
  • โอนยอดไม่ตรงจริง: ลูกค้าโอนเงินไม่ตรงตามราคาค่าบริการโดยตรวจจับไม่ทันที
🤝 2. ปัญหาการเคลียร์เงินช่าง (เงินออก)
  • คำนวณส่วนแบ่งด้วยมือ: คิดค่าคอมมิชชันตอนสิ้นวันด้วยตนเอง มักเกิดข้อผิดพลาดจากการคำนวณของมนุษย์
  • ขาดการแจ้งเตือนเรียลไทม์: ช่างไม่ทราบยอดสะสมระหว่างวัน ทำให้เกิดความเคลือบแคลงสงสัยและข้อพิพาท
  • ตัดรอบเคลียร์เงินล่าช้า: ขาดระบบสรุปยอดค้างจ่าย (Settlement) และแนบสลิปหลักฐานการโอนจ่ายช่าง
🗄️ 3. ขาดระบบจัดการและรายงานธุรกิจ
  • บันทึกในสมุด/ตารางคำนวณ: ข้อมูลสูญหาย รายการตกหล่น และขาดฐานข้อมูลกลาง (CRUD) ในการจัดการ
  • ขาดใบเสร็จรับเงินที่น่าเชื่อถือ: ไม่มีระบบออกใบเสร็จรับเงินอิเล็กทรอนิกส์ (e-Receipt) ให้แก่ลูกค้า
  • ขาดเครื่องมือวิเคราะห์ผู้บริหาร: เจ้าของร้านขาดแดชบอร์ดสรุปยอดขาย รายได้สุทธิ และผลงานช่างในภาพรวม

SLIDE 04 / 20
1. ระบบรับชำระเงินผ่าน LINE LIFF (1.3.1)

ระบบรองรับการทำรายการของผู้ใช้งาน โดยสามารถเลือกบริการ เลือกช่างตัดผม และอัปโหลดหลักฐานการโอนเงินผ่านทางหน้าเว็บแอปพลิเคชัน LIFF (LINE Front-end Framework) บนแอปพลิเคชัน LINE

2. ตรวจสอบสลิปอัตโนมัติ Slip2Go API (1.3.2)

ระบบมีฟังก์ชันตรวจสอบความถูกต้องของสลิปโอนเงินโดยอัตโนมัติ ผ่านการเชื่อมต่อกับระบบ Slip2Go API ตรวจสอบยอดเงิน บัญชีผู้รับ และป้องกันการนำสลิปเก่ามาวนใช้ซ้ำ

3. คำนวณส่วนแบ่งช่าง & ฐานข้อมูล MySQL (1.3.3)

ระบบสามารถคำนวณส่วนแบ่งรายได้ของช่างตัดผม และบันทึกข้อมูลประวัติการทำธุรกรรมทั้งหมดลงในระบบฐานข้อมูล MySQL โดยอัตโนมัติ

4. ส่ง Flex Message & แจ้งเตือนเรียลไทม์ (1.3.4)

ระบบสามารถส่ง เฟล็กซ์เมสเสจ (e-Receipt) ให้แก่ลูกค้า พร้อมทั้งแจ้งเตือนสรุปยอดเงินให้ช่างตัดผมและเจ้าของร้านทราบ ผ่านทางแอปพลิเคชัน LINE

5. กระดานข้อมูลสรุปยอดขาย Data Studio (1.3.5)

ระบบมีหน้ากระดานข้อมูล (Dashboard) สำหรับแสดงผลสรุปยอดขาย สถิติการใช้บริการ และรายได้ของช่างตัดผมแต่ละรายแบบเรียลไทม์ ผ่านเครื่องมือ Data Studio (Google Looker Studio)

ผังการเชื่อมโยงระบบแบบไร้รอยต่อ (End-to-End Workflow) ระหว่าง LINE, n8n, APIs และ Cloud Database

🔍 ภาพที่ 3.1 ผังการทำงานภาพรวมของระบบ (System Architecture)
5 เสาหลักเทคโนโลยีของระบบ
  • Client Interface: LINE Official Account และ LINE LIFF SDK (HTML5, Tailwind CSS, JS) เข้าถึงสะดวกไม่ต้องลงแอป

  • Analytics Layer: Data Studio (Google Looker Studio) สร้างแดชบอร์ดสรุปยอดขายสด

  • ขั้นที่ 2 ตรวจสอบสลิปซ้ำ: ตรวจสอบเลขอ้างอิงในตาราง transactions ของ MySQL หากพบว่าเคยใช้แล้วจะปฏิเสธทันที
  • ขั้นที่ 3 ตรวจสอบบัญชีผู้รับ: ตรวจสอบชื่อบัญชีผู้รับเงินว่าตรงกับ 'นายสราวุฒิ อุยยาหาญ' หรือไม่
  • ขั้นที่ 4 ตรวจสอบยอดเงิน: ตรวจสอบยอดเงินโอนจริงว่าเท่ากับหรือมากกว่าราคาค่าบริการที่เลือกหรือไม่
  • ผลลัพธ์: หากผ่านครบทุกเงื่อนไข ให้ออกบิลและยิง Flex e-Receipt สีเขียวทันที / หากไม่ผ่าน จะแจ้งเตือนข้อผิดพลาด

❓ 1. ทำไมใช้ n8n Automation แทนการเขียนโค้ด Backend เพียวๆ ด้วย Node.js หรือ Python?
ตอบ: n8n เป็น Workflow Orchestration ระดับ Enterprise ที่รันแบบ Self-Hosted บน Railway ช่วยลด Development Time ได้กว่า 60%, มี Visual Debugger และ Execution History ให้เห็น Error และ State ของธุรกรรมการเงินแบบ Real-time อีกทั้งยังจัดการ Webhook Retry, Error Handling และ Queue ได้ในตัว ทำให้การบำรุงรักษาในระยะยาวทำได้ง่ายและเสถียรครับ
❓ 2. ป้องกันสลิปปลอมและการนำสลิปเก่ามาวนใช้ซ้ำ (Slip Reuse) อย่างไร?
ตอบ: ระบบเชื่อมต่อ Slip2Go API ซึ่งสแกน QR Code เพื่อดึงเลขอ้างอิงธนาคาร (Bank Transaction Ref) เมื่อได้เลข Ref ระบบจะเช็กในตาราง transactions ของ MySQL ทันที หากพบว่าเคยใช้แล้วจะปฏิเสธทันที นอกจากนี้มี IF Node ตรวจสอบชื่อบัญชีผู้รับเงิน 'นายสราวุฒิ อุยยาหาญ' และยอดเงินตรงตามราคาบริการเป๊ะครับ
❓ 3. ถ้าลูกค้า 2 คนสแกนจ่ายพร้อมกัน (Concurrency / Race Condition) ฐานข้อมูลรับไหวไหม?
ตอบ: ฐานข้อมูล MySQL รันบน Railway Cloud พร้อม InnoDB Engine ที่รองรับ Row-level Locking และ Webhook ของ n8n เป็น Asynchronous Queue รับประกันว่าข้อมูลจะไม่สูญหายและไม่เกิด Race Condition บันทึกซ้ำซ้อนแน่นอนครับ
❓ 4. สูตรคำนวณส่วนแบ่งค่าคอมมิชชันช่างมีความยืดหยุ่นอย่างไร?
ตอบ: ตาราง users กำหนดอัตราส่วนแบ่ง (Commission Rate) แยกตามทักษะช่างแต่ละคนได้ (เช่น 50%, 60%) เมื่อมีบิลเข้า ระบบจะคำนวณและบันทึกลงฟิลด์ barber_earn และ shop_earn ในตาราง transactions ทันทีแบบคงที่ ป้องกันความคลาดเคลื่อนย้อนหลังแม้มีการปรับอัตราเปอร์เซ็นต์ในอนาคตครับ
❓ 5. กรณีเงินสดหน้าร้าน (Cash) ป้องกันช่างไม่คีย์บิลได้อย่างไร?
ตอบ: หน้าร้านมีป้ายแจ้งเตือน "โปรดขอใบเสร็จรับเงิน e-Receipt ทุกครั้ง" และลูกค้าที่ทำรายการผ่าน LIFF จะได้รับใบเสร็จสีเขียวใน LINE ทันที นอกจากนี้เจ้าของร้านสามารถตรวจเช็กสต็อกบริการและจำนวนลูกค้าหน้าร้านเปรียบเทียบกับยอดบิลในระบบได้ตลอดเวลาครับ
❓ 6. ระบบโมฆะบิล (Void Bill) มีความเสี่ยงถูกแอบยกเลิกบิลโดยพลการไหม?
ตอบ: การทำโมฆะบิลต้องทำผ่าน Admin Backoffice เท่านั้น และระบบจะบันทึก Audit Log ไม่ลบแถวทิ้ง แต่ปรับยอดเป็น 0 พร้อมขึ้นแถบแดง และยิง LINE Push Notification เตือนช่างทันทีแบบ Real-time ทำให้ช่างทราบทันทีว่าบิลไหนถูกยกเลิก ไม่สามารถแอบทำโดยพลการได้ครับ
❓ 7. ถ้า Slip2Go API หรือเครือข่ายธนาคารขัดข้อง ลูกค้าจะจ่ายเงินอย่างไร?
ตอบ: ระบบมี Fallback Mechanism โดยลูกค้าสามารถเลือกชำระเป็น "เงินสดหน้าร้าน (Cash)" หรือแนบสลิปเพื่อให้แอดมินตรวจสอบแบบ Manual ที่หน้าเว็บหลังบ้านได้ทันที การทำงานของร้านจึงไม่หยุดชะงักครับ
❓ 8. Looker Studio เชื่อมต่อ MySQL อย่างไร และข้อมูลอัปเดตเมื่อไหร่?
ตอบ: เชื่อมต่อผ่าน MySQL Native Connector บน Railway Cloud ผ่านพอร์ต SSL เข้ารหัส ปลอดภัย ดึงข้อมูล Query อัตโนมัติและแสดงผลแบบ Real-time เมื่อเปิดดูแดชบอร์ดครับ
